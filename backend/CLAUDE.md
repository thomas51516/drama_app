# backend/ — conventions for agents

NestJS 12 (ESM, `"type": "module"`, imports end with `.js`), TypeScript strict, Prisma 7 + `@prisma/adapter-pg`, Vitest, ESLint (typed) + Prettier. Functional spec: `../docs/Cahier des charges…md` §8; tickets: `../docs/Backlog…md`.

## Layout

- One folder per business module (spec §8.2): `auth` (guest, refresh, `identity/` Google + linking/merge, `otp/`, `sms/` port), `catalog` (`CatalogService` + `HomeService` + `SearchService` + `PersonalizationService`), `playback`, `unlock`, `wallet`, `billing`, `rewards`, `users` (profile, deferred deletion + `AccountDeletionService`, favorites/likes), `push/` (global: `PushProvider` port `log` | `fcm`, `PushService.notify()`, `NewEpisodeNotifier`, `CampaignSenderService`, BullMQ queue `push`), `help/` (FAQ + support, public and admin controllers), `analytics/` (`POST /events`), `admin` (sub-modules `auth/` incl. `TrustedDeviceService`, `series/`, `episodes/`, `subtitles/`, `home/`, `accounts/`, `audit/`, `schedule/`, `stats/`, `campaigns/`), plus `health`, `metrics`, `storage` (S3), `media/` (global `MediaUrlSigner` port, `plain` | `hmac`), `transcode` (BullMQ + ffmpeg / webhook), `cache/` (global `CatalogCacheService`), `jobs/` (`SchedulerService`: per-minute tick with Redis lock running `PublishSchedulerService` and the account anonymiser). Each has `<name>.module.ts`, `<name>.controller.ts`, `<name>.service.ts`, `dto/` for request/response classes.
- Cross-cutting code lives in `common/` (decorators, exception filter, request logger, `ApiErrorDto`, `rate-limit/`, `crypto/`, `i18n/` for `Accept-Language` / `X-Country` / language labels, `subtitles/` for the dependency-free SRT→VTT converter), `config/` (zod env schema + `AppConfig`), `prisma/`, `redis/`, `openapi/`, `observability/` (Sentry).
- `src/generated/prisma/` is generated and git-ignored: never edit, run `npm run prisma:generate`.
- Not-yet-implemented endpoints throw `notImplemented('<ticket>')` (501) but ARE documented in OpenAPI v1 with real request/response DTOs and `@ApiNotImplementedResponse` (the Android mock is generated from them). Keep their DTOs stable; mark every stub with `// TODO <ticket>`.
- New env var = `env.schema.ts` + `AppConfig` getter + `.env.example` + README table + CI workflow env + `openapi-export.ts` fallbacks if it is required.

## HTTP conventions

- Protected by default: the global `JwtAuthGuard` requires a bearer token unless the handler/class has `@Public()`. Public routes still populate `req.user` when a valid token is sent. Read the user with `@CurrentUser()`.
- Back-office routes: class-level `@AdminRoute()` + `@UseGuards(AdminAuthGuard)` + `@ApiBearerAuth('admin')`, role restrictions with `@Roles('EDITOR', 'ADMIN')`, actor with `@CurrentAdmin()`. Admin JWTs use `ADMIN_JWT_SECRET` / `aud: admin`; never accept them in `JwtAuthGuard` or user JWTs in `AdminAuthGuard`. Contracts: `docs/api/admin-contract-v1.md` and `docs/api/contract-v1.3-sprint5.md` (binding; any change goes through those files first). Trusted devices (B-13+): raw token only ever returned once by `/totp/verify`, stored as SHA-256 in `admin_trusted_devices`; `TrustedDeviceService.revokeAll()` must be called inside any transaction that resets TOTP or deactivates an account.
- Every admin mutation records an `AuditService` entry (actor, action `<target>.<verb>`, old/new values of the changed fields, IP), inside the same `$transaction` as the write when there is one.
- Rate-limited routes declare `@RateLimit({ name, limit, windowSeconds, scope: 'ip' | 'email' | 'phone' })`; the guard answers 429 `RATE_LIMITED` and fails open when Redis is down. Per-user daily limits that depend on config (`SUPPORT_CONTACT_DAILY_LIMIT`) are enforced in the service with a Redis key under the same `rl:` prefix (so e2e resets cover them).
- Notifications: every user-facing notification goes through `PushService.notify()` (in-app `notifications` row + push on all devices + daily cap `PUSH_DAILY_CAP` in Redis `push:cap:*`, all causes); never call the `PushProvider` directly from a feature. Campaign fan-out lives in `CampaignSenderService` (segment SQL on alias `u`, batches of `PUSH_BATCH_SIZE`). The new-episode trigger is `NewEpisodeNotifier.onEpisodeVisible()` (fire-and-forget, from `TranscodeService.markReady`) / `notifyEpisode()` (awaited, from `PublishSchedulerService`); it only fires for READY + published episodes of published series and claims a per-series-per-hour Redis key. Unit tests mock the provider; e2e use `PUSH_PROVIDER=log` and `PUSH_QUEUE_ENABLED=false` (inline send).
- Analytics: `POST /events` accepts only `ANALYTICS_EVENT_NAMES` (spec §13 + login/signup/share/search); add a name there and in the OpenAPI description together. `analytics_events` has no FK on purpose (write-only, survives anonymisation).
- Public contract: `docs/api/public-contract-v1.2.md` (binding for `/auth/*`, `/me*`, `/search`, `/feed`, `/play`). New sign-in routes return `AuthSessionDto { accessToken, refreshToken, expiresIn, user: UserDto, linked }` built by `AuthService.openSession()`; `/auth/guest` and `/auth/refresh` keep the v1.0 `AuthResponseDto`. Linking/merge rules live only in `IdentityAuthService` + `AccountMergeService` (merge = one `$transaction`, ledger transfer via paired `ADJUSTMENT` rows, guest → `MERGED`, tokens revoked, audit `user.merge` with `actorLabel: user:<id>`). `JwtAuthGuard` stays stateless: a `DELETION_PENDING` user can still sign in (to cancel), `BLOCKED | MERGED | DELETED` cannot (`LOCKED_USER_STATUSES`).
- Media URLs: `/play` `manifestUrl` and `/feed` `previewUrl` go through `MEDIA_URL_SIGNER` (`sign(url)` → `{ url, expiresAt }`); thumbnails, posters and subtitles are never signed. Dev `.env` must stay `MEDIA_SIGNER=plain` (MinIO cannot check tokens).
- Webhooks (`/webhooks/*`) are `@Public()` and authenticated by signature over `req.rawBody` (app created with `rawBody: true`), never by JWT.
- Validate every input with class-validator DTOs (global `ValidationPipe`: whitelist + forbidNonWhitelisted + transform). Query DTOs need `@Type(() => Number)` for numbers. File uploads that must go through the API (subtitles only, 2 MB) use `FileInterceptor` with `limits` and a plain `UploadedSubtitleFile` interface; videos and posters never transit through the API (presigned PUT).
- Public catalog responses are cached by `CatalogCacheService` (`GET /home` 60 s per country+language, `GET /series/{id}` and `/episodes` 120 s per country, anonymous variant). Never put per-user data in a cached payload: compute `access`/`coinCost`, « Continuer à regarder » and `isFavorite`/`likes` (`PersonalizationService.decorate()`, only when a token is present) after the cache (`withAccess()`, `HomeService`). Any write that changes what the public sees must call `cache.invalidateSeries(seriesId)` (series patch/publish/archive, episode update/delete/reorder, `TranscodeService.markReady`, subtitles) or `cache.invalidateHome()` (home banners/rows). Services that invalidate take `CatalogCacheService` as a constructor dependency; pass a mock in unit specs.
- Viewer context comes from `CatalogService.viewerContext(userId, { country, acceptLanguage })`: `X-Country` header, else account country, else no territorial filter; language from `Accept-Language` restricted to `fr|en|es|pt` (default fr).
- Document every endpoint with `@ApiOperation`, response types and `ApiErrorDto` for errors. Run `npm run openapi:export` after changing the contract; CI fails if `docs/api/openapi.v1.json` is stale (`openapi.v0.1.json` is history, do not regenerate it). Bump `OPENAPI_VERSION` in `src/openapi/openapi.ts` on breaking changes.
- Errors: throw Nest `HttpException`s with `{ code: 'STABLE_CODE', message, details? }`; `AllExceptionsFilter` normalises everything to `ApiErrorDto`. Codes are SCREAMING_SNAKE_CASE and are the contract with the app; messages are English and not shown to users.
- Code, identifiers and commits in English; Swagger descriptions, README and user-facing text in French.

## Prisma rules

- Tables/columns are snake_case via `@@map`/`@map`; models and fields camelCase. IDs are `uuid(7)`. Timestamps are `Timestamptz(3)` with `createdAt`/`updatedAt`.
- Schema change = `npm run prisma:migrate -- --name <snake_case_name>` and commit `prisma/migrations/*`. Never edit a merged migration; check with `npm run prisma:reset` that migrations replay from scratch.
- Use `prisma.$transaction(async (tx) => …)` whenever two writes must be atomic (user + wallet, ledger + unlock, token rotation).
- Public catalog queries must go through `publishedSeriesWhere()` / `visibleEpisodeWhere()` (`catalog/catalog.where.ts`; both require `publishedAt <= now`, which is what makes scheduled publication B-04 work — raw SQL in `SearchService` repeats the same predicate), and access decisions through `EntitlementService` + `computeAccess()`.
- `series.search_vector` (`Unsupported("tsvector")`) is maintained by the trigger `series_search_vector_refresh` (migration `20261029192258`); never write it from the application. `series.likes_count` is a projection of `likes`, changed only in the same transaction as the `likes` row (`FavoritesService`, merge, anonymiser). Insert with `ON CONFLICT DO NOTHING` inside transactions rather than catching `P2002` (PostgreSQL aborts the transaction).
- User identities live in `user_identities (provider, subject)` unique; `users.email` / `users.phone` are display/unique copies. Account anonymisation (`AccountDeletionService`) deletes favorites, likes, progress, identities and contact data but keeps ledger, wallet, purchases and unlocks (status `DELETED`).
- `faq_entries.question/answer` and `home_rows.titles` are JSON `{ fr, en?, es?, pt? }` with `fr` mandatory; read them with `localize()` (fallback fr).
- Episode transcode status transitions go through `TranscodeService` (`submit`, `markProcessing`, `markReady`, `markFailed`), never by updating `transcodeStatus` directly elsewhere. Storage keys: `sources/{seriesId}/{episodeId}/{fileName}`, `hls/{episodeId}/…`, `posters/{uuid}/{fileName}`, `subtitles/{episodeId}/{language}.vtt` (stored as the relative key in `subtitles.file_url`); public URLs via `StorageService.publicUrl()` / `resolveMediaUrl()`.
- Home configuration lives in `home_banners` / `home_rows` (B-05); `GET /home` is built only from it (`HomeService`), never from hard-coded rows. `home_rows.titles` is JSON `{ fr, en?, es?, pt? }` with `fr` mandatory. Admin accounts: ADMIN-only routes, never let a request remove the last active ADMIN or the caller's own ADMIN role; `reset-totp` clears both `totp_secret` and `totp_enabled_at`. Never touch the seed account `admin@drama.local` TOTP in tests or scripts (create `e2e-*@drama.local` accounts and delete them, audit logs first).

## Ledger rule (non-negotiable)

Every coin movement is an append-only `coin_ledger` row (`amount` signed, `bucket`, `type`, unique `idempotencyKey`, `expiresAt` for bonus). `wallets.purchased_balance` / `bonus_balance` are projections updated in the same transaction as the ledger insert and must equal the sum of the ledger. No direct balance updates, no ledger UPDATE/DELETE (corrections are `ADJUSTMENT`/`REFUND` rows). Bonus coins are spent before purchased coins. The server is the only source of truth for balances, entitlements and prices.

## Tests

- Unit: `npm test` (Vitest, `src/**/*.spec.ts`, globals enabled). Mock Prisma/Redis/S3/ffmpeg with plain objects and `vi.fn()`; construct services directly (`new Service(prisma as never, …)`) rather than booting a Nest module. `FfmpegRunner` is the seam for the transcode pipeline.
- E2E: `npm run test:e2e` (`test/**/*.e2e-spec.ts`) needs the compose stack (PostgreSQL, Redis, MinIO) and `npm run prisma:deploy`. Create apps with `createNestApplication({ rawBody: true })`. Force `process.env.TRANSCODE_PROVIDER = 'webhook'`, `SCHEDULER_ENABLED = 'false'`, `SMS_PROVIDER = 'console'`, `PUSH_PROVIDER = 'log'`, `PUSH_QUEUE_ENABLED = 'false'` in e2e files so no ffmpeg job or timer runs; reset `rl:*` keys in `beforeAll` (Redis is shared with the dev API, also avoid shared cache keys such as the stats overview); users with ledger rows must have their `coin_ledger` rows deleted before the user (FK Restrict); the real pipeline is exercised by `npx tsx scripts/smoke-ingest.ts` against a running API. Clean up rows you create (series cascade episodes; delete audit logs of test actors before the accounts).
- Before handing over: `npm run lint && npm run build && npm test` must pass; run `npm run test:e2e` when you touched auth, admin, catalog, playback, transcode or the schema. ffmpeg 6+ must be installed for the smoke test.
