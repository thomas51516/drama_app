# web/ — conventions for agents

Nuxt 3 workspace (npm workspaces): one base layer, several apps. Read `web/README.md` for the full picture.

- `layers/base` is the only place for shared code: Tailwind, PrimeVue (Aura), Pinia, i18n, `useApi()`, auth store, layouts, layout components, mocks, API types.
- `apps/admin` and `apps/recharge` both extend the layer and hold pages only (plus app-specific config): `apps/admin` is the back-office (`ssr: false`, port 3100), `apps/recharge` is the public mobile-money top-up site (`ssr: true`, port 3200, FR default + EN/ES/PT, every page under 300 KB gzip of JS+CSS).
- Import layer code from an app with the `#base/...` alias, never with `../../layers/...`.
- Every HTTP call goes through `useApi()` (or the typed wrappers `useCatalogueApi()`, `useSubtitlesApi()`, `useFeaturedApi()`, `useAdministrationApi()`, `useScheduleApi()`, `useStatsApi()`, `useAccountApi()`, `useCampaignsApi()`, `useHelpCenterApi()`, `useMonetizationApi()`, `useOffersApi()`, `useTopupApi()`, `useUsersApi()`); never call `$fetch` directly in pages or stores. `useApi()` authenticates through an `ApiSession` (the admin JWT store by default; `apps/recharge/plugins/api-session.ts` swaps it for the end-user session of `stores/recharge-session.ts`, with a one-shot `tryRefresh()` on 401 before giving up) — a new app that needs a third kind of session provides its own `nuxtApp.$apiSession` plugin rather than branching inside `useApi()`. Multipart uploads to the API (subtitles) pass a `FormData` body to `useApi().post()`. Types of the API live in `layers/base/types/api.ts` and must match `docs/api/admin-contract-v1.md` (the back-office section of `docs/api/public-contract-v1.2.md` for B-04/B-11, `docs/api/contract-v1.3-sprint5.md` for trusted devices, campaigns, FAQ and support, `docs/api/contract-v1.4-sprint6.md` for monetization, rewards and users, and `docs/api/contract-v1.5-sprint7.md` for reward tasks, offers/promo codes, top-up/reconciliation and the public routes the recharge site reuses) exactly (enum values are uppercase: `DRAFT`, `READY`, `ADMIN`...). **Checked against the running backend (sprint 7) and confirmed to diverge from the contract text**: a limited offer's `startsAt` must be a valid ISO string, never `null` (`limitedOfferToInput()` substitutes "now"); a promo code's usage counter is `usesCount`, not `usedCount`; a top-up order's `coins` is the base amount only, the bonus comes separately in `bonusCoins` (`orderTotalCoins()` sums them); the reconciliation report's collected amount is `amounts: Price[]` (one entry per currency), not a single `amountPaid`. Re-check against the real API before trusting the contract markdown on a field you have not seen a live response for.
- User feedback: `useNotify()` for toasts (success/errors, `apiError(err)` for failed calls), `useConfirm()` for destructive actions. `useApi()` already handles 401 (redirect) and 403 (toast "Droits insuffisants"); do not toast those again.
- Media keys (`hlsKey`, thumbnails, `mock://assets/...`) are resolved with `useMediaUrl().resolve()`, never by concatenating URLs in templates.
- Video and poster uploads never go through the API: presign/upload-url then direct PUT with `utils/upload-transport.ts` (`xhrUploadTransport`, or `mockUploadTransport` when `api.isMock`). Bulk upload logic lives in `utils/upload-queue.ts` (pure, tested); keep UI components thin.
- Mock mode (`runtimeConfig.public.apiMock`) must keep working: add a `route(method, path, handler)` in `layers/base/mocks/index.ts` (stateful, path params with `:id`, contract error codes) and a fixture JSON for each new endpoint. Tests shorten `mockTiming` / `mockUploadTiming` and call `resetMockState()`.
- Pages are private by default (`middleware/auth.global.ts`); opt out with `definePageMeta({ public: true })`.
- UI strings are i18n keys (`layers/base/i18n/locales/fr.json` first, `en.json` second). Never hardcode French in templates.
- Back-office navigation comes from `layers/base/utils/modules.ts` (B-01 to B-13 plus B-03bis). A module may declare `roles` (hidden from the sidebar and `LayoutForbidden` in the page for other roles), a `badge` fed by a store (`supportInbox` = open tickets), and `children` (sub-pages under it in the sidebar, their own role gating — `findSubpageByPath()`). Replace a `ComingSoon` route by adding a real page at the same path. Real pages so far: `/series`, `/episodes`, `/subtitles`, `/schedule`, `/featured`, `/monetization` (B-06), `/offers` (B-07), `/rewards` (B-08), `/users` and `/users/[id]` (B-09), `/campaigns` (B-10), `/help-center` (B-03bis), `/dashboard`, `/topup-reconciliation` (B-11, a `children` sub-page of `/dashboard`), `/administration`, `/account` (« Mon compte », trusted devices), plus `/help` (guide rendered from `web/docs/guide-back-office.md`). `apps/recharge` has its own page set (`/`, `/login`, `/packs`, `/pay/[orderId]`, `/history`, `/account`, `/legal/*`, `/mock-payment/[orderId]` in mock mode only) — see `web/README.md` § « Site de recharge ».
- Auth cookies: `drama_admin_token` (JWT, 8 h) and `drama_admin_device` (trusted-device token, 30 days, contract v1.3). `clearSession()` (logout, 401 including `ADMIN_TOKEN_REVOKED`) never touches the device cookie; only `forgetDevice()` does, after revoking the device through `useAccountApi()`. `login()` returns `'done'` when the server answered `status: "ok"`: callers must handle it (no TOTP step). `TrustedDevice.current` is always sent since contract v1.4 and drives « Cet appareil » / « Révoquer cet appareil ». Login error messages come from `utils/auth-errors.ts` (`loginErrorKey(err, step)`, DEF-005): never show a raw status for a 4xx of the login flow.
- Role gating in pages: compute `canEdit` from `useAuthStore().user.role` (helpers in `utils/series-form.ts`), render `LayoutForbidden` for pages a role may not open (B-13 is ADMIN-only) and keep server errors as the source of truth (`notify.apiError`).
- Components that load data inside lazy tabs/dialogs must not `await useAsyncData` at top level (no Suspense boundary there): call it without `await` and drive the UI with `status`.
- Form logic stays in pure utils (`utils/featured.ts`, `utils/accounts.ts`, `utils/subtitles.ts`, `utils/audit-diff.ts`, `utils/schedule.ts`, `utils/stats.ts`, `utils/campaigns.ts`, `utils/help-center.ts`, `utils/monetization.ts`, `utils/rewards.ts`, `utils/offers.ts`, `utils/reconciliation.ts`, `utils/topup.ts`, `utils/users.ts`) returning i18n keys as error codes; components only translate and display. Prices (B-06) are `{ currency, amountMinor }` on the wire: forms edit major units through `PriceForm` and convert with `toMinor()` / `toMajor()` (XOF has 0 decimals); `fillPricesFromXof()` only pre-fills with indicative rates, never silently overwrites. Coin adjustments (B-09) go through `adjustmentToInput()` (signed amount, trimmed reason ≥ 10 chars) and the preview is `adjustmentPreview()`; 4xx codes map to French with `userErrorKey()`. The user detail paginates its embedded lists client-side (`paginate()`, 20 per page). Campaign `segment` payloads go through `segmentFromForm()` (only the field of the chosen type); FAQ previews go through `faqPreview()` (same rules as the public `GET /help/faq`: published only, French fallback). Reward tasks (B-08, M-41) are six fixed keys (`REWARD_TASK_KEYS`): the admin only edits `coins`/`target`/`isActive` via `taskPatch()` (changed fields only), titles come from the backend. Offers and promo codes (B-07) go through `welcomeFormToInput()`/`limitedOfferToInput()`/`promoCodeToInput()`; promo codes are generated with `generatePromoCode()`/`generatePromoCodes()` (unambiguous alphabet, no O/0/I/1) and have no delete route — deactivate instead. The recharge order state machine (`payStep()`, `effectiveStatus()`, `canRetry()`) and its memo store (`stores/topup-orders.ts`) live in `utils/topup.ts`; reconciliation CSV export is `reconciliationToCsv()` (RFC 4180, UTF-8 BOM) in `utils/reconciliation.ts`.
- Dates of publication (B-04): the API stores UTC, the UI shows and enters Lomé wall time (`SCHEDULE_TIME_ZONE`). Always convert with `toPickerDate()` / `fromPickerDate()` and format with `formatZoned()` from `utils/schedule.ts`; never feed a raw ISO string to a DatePicker or `new Date(...)` to a template.
- Charts (B-11): PrimeVue `Chart` over `chart.js`, only where a table is not enough; follow the `dataviz` skill (fixed categorical palette `STATS_SERIES_COLORS`, legend for 2+ series, a table next to every chart). Stat tiles are plain components, not charts.
- Markdown shown in the app goes through `utils/markdown.ts` (source escaped, allowed tags only); do not add a Markdown library for the help page.
- Code, identifiers and comments in English; UI and READMEs in French.
- Before handing over: `npm run lint && npm run typecheck && npm run test && npm run build:admin && npm run build:recharge` from `web/`. If a dev server is running on the same checkout (`npm run dev:admin` port 3100, `npm run dev:recharge` port 3200), run **all** of these with `export NUXT_BUILD_DIR=/tmp/drama-web-check` first (and `NUXT_BUILD_DIR=... npx nuxt dev --port 3101` from `apps/admin` / `--port 3201` from `apps/recharge` for second dev instances against the real backend): typecheck and the Vitest Nuxt environment otherwise rewrite the dev server's `.nuxt/` and the test setup hangs until the hook timeout. Build both apps with `NUXT_PUBLIC_API_MOCK=false` to catch anything that only works in mock mode.
- Tests run in the Nuxt runtime (`environment: 'nuxt'`, rootDir `apps/admin`, mock API forced on) — this also covers `apps/recharge`'s pure utils and the recharge mock flows, since they live in `layers/base`; there is no separate Vitest project for the recharge app. Put layer tests in `layers/base/tests`, app tests in `apps/<app>/tests`. Prefer testing pure utils (`series-form`, `upload-queue`, `polling`, `topup`, `offers`, `reconciliation`) and the mock flow (`mockRequest()` directly for the public/recharge routes, since `useApi()`'s default session is the admin store) over mounting PrimeVue-heavy pages.
- Do not edit generated files (`.nuxt/`, `eslint-typegen.d.ts`). ESLint config is the single `web/eslint.config.mjs`.
